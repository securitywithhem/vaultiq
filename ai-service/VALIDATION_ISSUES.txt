Validation Issues - Task 6: Retrained LR Model
=============================================
Date: 2026-04-18
Model: Logistic Regression (optimized hyperparameters)
Training Data: 500,000 Kaggle examples
Training Accuracy: 73.57%

VALIDATION RESULTS
==================
Validation Method: 16 test samples (8 human academic + 8 AI-like content)
Accuracy: 68.8% (11/16 correct)
Target: 75% (12/16 correct)
Status: FAILED by 3 samples

DETAILED BREAKDOWN
==================
- Human samples correct: 3/8 (37.5%) - TOO LOW
- AI-like samples correct: 8/8 (100.0%) - EXCELLENT
- High-confidence predictions: 7/16
- False positive rate: 62.5% (5/8 human classified as AI)
- False negative rate: 0% (0/8 AI classified as human)

ROOT CAUSE ANALYSIS
===================
The model shows:
1. HIGH PRECISION on AI detection (100% correct on AI-like samples)
2. LOW RECALL on human detection (37.5% correct on human samples)
3. Model trained on Kaggle data with primarily binary labels
4. Academic writing often contains:
   - Structured, formal language patterns
   - Technical terminology and jargon
   - Complex sentence structures
   - These characteristics overlap with AI-generated text patterns

IMPACT ASSESSMENT
=================
- Model will over-flag human academic submissions as AI-generated
- False positive rate is unacceptable for production deployment
- Academic institution feedback would be poor
- Students would incorrectly receive AI-detection warnings

ISSUES WITH RETRAINING APPROACH
================================
1. Kaggle dataset has different distribution than academic content
   - Kaggle: Mixed sources (news, web, GPT-2, etc.)
   - Academic: Lab reports, essays, technical assignments

2. Model lacks context-aware features
   - Only uses statistical features (word count, punctuation, entropy)
   - Missing: domain-specific patterns, submission context

3. Class imbalance not properly handled
   - class_weight='balanced' helps but insufficient
   - Need more human academic training examples

NEXT STEPS
==========
1. OPTION A: Reduce decision threshold
   - Lower the threshold for "high confidence" from 0.7 to 0.65
   - Trade-off: May miss some actual AI content
   - Effort: Minimal (configuration change)

2. OPTION B: Rebalance training data
   - Add more human academic examples to training set
   - Reduce weight of Kaggle data or apply stratified sampling
   - Effort: Medium (requires new training)

3. OPTION C: Use ensemble with RoBERTa
   - Combine LR with RoBERTa-based detection
   - RoBERTa may better capture AI-generated patterns
   - Effort: High (integration with existing system)

4. OPTION D: Collect labeled academic data
   - Build custom dataset with real academic submissions
   - Label as human/AI-generated by domain experts
   - Retrain with domain-specific data
   - Effort: Very High (data collection required)

RECOMMENDED APPROACH
====================
Proceed with OPTION A as immediate fix:
- Lower confidence threshold to reduce false positives
- Validate with same test set
- Monitor in production for 2 weeks
- Collect feedback from academic users
- Plan for OPTION B (rebalancing) in next sprint

Current Status: Model REJECTED for production deployment
Reason: 68.8% accuracy (need 75%+) with excessive false positives

Approval Decision: HOLD - Requires threshold adjustment and re-validation
